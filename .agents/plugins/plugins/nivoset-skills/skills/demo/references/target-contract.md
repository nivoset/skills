# Target contract

Provide a reachable HTTP(S) `url`, or an explicit `command` plus `url` or `healthUrl`. Verify a supplied URL is reachable before the run; the CLI does not health-probe URL-only targets. A reachable URL can point to Podman, Docker, or another local service: use it as-is, without restarting or cleaning up that service. If startup instructions but no URL are supplied, use them when safe and derive the URL from the verified port mapping. If neither URL nor startup instructions are supplied, inspect repository evidence, start the documented target with an available Podman or Docker engine, and supply the URL derived from its actual host port mapping. Choose a free host port and unique run-owned project prefix. Track and manually remove only resources created for that run; the CLI does not manage container teardown. Podman Compose delegates to a provider, so verify that provider's project naming and created resources before cleanup.

When both URLs are present, they must share an origin: readiness probes use `healthUrl`, while navigation resolves from `url`. The review storyboard shows both values. `baseUrl` is rejected. The runner never guesses startup commands. For `current-behavior`, `command` launches only the specified long-lived process; it does not manage a detached Compose stack. For `before-after`, start each target yourself and provide its URL; command targets are not launched. Navigation and URL assertions remain limited to HTTP(S) and same-origin relative paths.
